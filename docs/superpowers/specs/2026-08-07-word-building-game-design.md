# 絵からことばをつくるゲーム デザイン仕様

## 目的

既存のManabiNoteに、表示された絵を見て、バラバラに配置された文字を順番に選び、言葉を完成させる独立ゲームを追加する。

既存の「ひらがなから絵を選ぶ」ゲームとは、画面・進行状態・問題形式を分離する。一方で、作成済みの絵と読みの対応は既存の問題データから再利用し、画像と名前の二重管理を避ける。

## 対象範囲

### 含めるもの

- ホーム画面から独立したゲームページへ移動する導線
- 1プレイ5問のゲーム進行
- 既存問題データにある正解画像と読みの再利用
- 読みを1文字ずつに分解した文字タイルのシャッフル表示
- 文字タイルの選択、取り消し、完成判定
- 間違い後に同じ問題をやり直す動き
- 5問終了後の専用結果画面
- ひらがなと長音記号「ー」を使った読み

### 含めないもの

- 新しい画像の生成や追加
- ドラッグ＆ドロップ操作
- 音声再生
- 既存の履歴画面やlocalStorageへの記録
- バックエンドやログイン

## ユーザー体験

### 入口とルート

- ホーム画面に「ことばをつくろう」ボタンを追加する。
- ゲームページは `/word-builder` とする。
- ゲーム終了後は `/word-builder/result` の専用結果画面を表示する。
- 既存のかなクイズ、書き順練習、履歴画面の進行状態には影響させない。

### 1問の流れ

1. 進捗（例：`1もんめ / 5もん`）と絵を表示する。
2. 絵の名前に対応する読みを、1文字ずつバラバラにして文字タイルとして表示する。
3. ユーザーが文字タイルをタップすると、選択欄へ移動する。
4. 選択した文字は、選んだ順番に選択欄へ並べる。
5. 「もどす」を押すと、最後に選んだ1文字を文字タイル側へ戻す。
6. 選択文字数が答えの文字数と同じになったら「できた！」を表示する。
7. 「できた！」で判定する。
8. 正解なら成功表示と次の問題へのボタンを表示する。
9. 不正解なら「もういちど」と表示し、同じ問題を継続する。選択中の文字は残し、ユーザーが「もどす」で修正できるようにする。
10. 5問目を正解したら結果画面へ進む。

### 文字のルール

- 問題の読みをUnicode上の文字単位で分割する。
- ひらがなを使用する。
- 長音記号「ー」は1文字のタイルとして含める。
- 同じ文字が複数ある場合も、それぞれタイルとして表示する。
- 判定はタイルIDではなく、選ばれた文字の並びで行う。
- そのため、同じ文字が複数ある場合は、どの同じ文字タイルを選んでも正解になる。

例：`ばなな` の2つの `な` は、画面上では別タイルだが、判定上は区別しない。

### 結果画面

- 5問を完了したことを大きく知らせる。
- 「もういちど」ボタンで新しい5問を開始できる。
- 「ホームへ戻る」ボタンを表示する。
- 今回は誤答回数の保存や履歴表示は行わない。

## データ設計

### 既存データの再利用

`loadKanaToPictureQuestions()` で読み込んだ既存のかな・絵問題を、ゲーム専用のアダプターで変換する。

各既存問題について、`correctChoiceId` に一致する選択肢から次の値を取り出す。

- 問題ID
- `reading`
- 正解画像の `image`

既存の問題バンクは正解の読みが重複しないルールを持つため、読みをゲーム問題の一意な識別子として利用できる。画像参照は既存のアトラス参照をそのまま使い、新しい画像パスや複製データは作らない。

### ゲーム専用モデル

ゲーム側では既存の `KanaToPictureQuestion` を直接表示せず、次の責務を持つ専用モデルへ変換する。

- `WordBuilderQuestion`: 問題ID、読み、画像参照
- `WordTile`: タイルID、表示文字
- `WordBuilderSession`: 5問、現在位置、選択中タイル、問題ごとの状態

同じ文字を正しく扱うため、`WordTile` のIDは表示上のタイル管理にだけ使う。回答判定では `WordTile.character` を連結した文字列と `question.reading` を比較する。

### 問題選択

- 有効な既存問題から重複なしで5問をランダムに選ぶ。
- 文字タイルの順番も問題開始時にランダム化する。
- シャッフルは元の問題データや共有配列を変更しない。
- 問題数が5問未満、画像参照が不正、読みが空の場合はセッションを開始せず、再試行またはホームへ戻る案内を表示する。

## コンポーネントと責務

- `WordBuilderSessionProvider`: セッション開始、問題移動、タイル選択、取り消し、判定を管理する。
- `WordBuilderPage`: 進捗とゲームコンポーネントを配置し、ルート遷移を行う。
- `WordBuilderQuestion`: 絵、選択欄、文字タイル、操作ボタンを表示する。
- `WordBuilderFeedback`: 正解・不正解・再挑戦の状態を表示する。
- `WordBuilderResultPage`: 5問完了後の結果と再プレイ・ホーム導線を表示する。
- `wordBuilderQuestionAdapter`: 既存のかな・絵問題からゲーム専用問題へ変換する。
- `wordBuilderSession` model: 純粋な状態遷移と回答判定を保持する。

既存の `QuizSessionProvider` と `StrokePracticeProvider` は変更せず、新しいProviderを別に追加する。これにより、ゲーム間で選択中の文字や問題番号が混ざらない。

## 状態遷移

```text
未開始
  └─開始→ 出題中
             ├─文字選択→ 選択欄更新
             ├─もどす→ 最後の文字をタイルへ戻す
             └─できた！→ 判定中
                           ├─不正解→ 出題中（同じ問題・選択欄を維持）
                           └─正解→ 正解表示→ 次の問題 / 結果画面
```

## 見た目とアクセシビリティ

- 既存のManabiNoteのやさしい配色とページレイアウトを再利用する。
- 絵はカード内で大きく表示する。
- 文字タイルと操作ボタンは幼児が押しやすい大きさにする。
- 選択欄には選択順が視覚的に分かる余白を設ける。
- ボタンには文字ラベルを付け、無効状態を色と操作不能状態の両方で表す。
- 画像には、既存の読みを基にしたアクセシブルな代替テキストを設定する。
- キーボード操作でもタイルとボタンを順番に操作できる標準button要素を使う。

## エラー処理

- 既存問題データの読み込み失敗時は、ゲーム画面に問題を読み込めない旨とホームへのリンクを表示する。
- ゲーム専用データへの変換で不正な問題を検出した場合は、セッションを開始しない。
- セッションがない状態でゲームルートへ直接アクセスした場合は、開始案内とホームへのリンクを表示する。
- 結果画面へ直接アクセスして結果状態がない場合は、ゲーム開始案内を表示する。

## テスト方針

### モデルテスト

- 既存問題からゲーム問題へ正しく変換できる。
- 5問を重複なく選べる。
- 文字タイルをシャッフルしても元データが変わらない。
- タイル選択と「もどす」が正しく状態を更新する。
- 正しい文字列を正解と判定する。
- 間違った文字列を不正解と判定し、同じ問題を継続できる。
- 同じ文字が複数ある場合、タイルIDが異なっていても正解になる。
- 「ー」を含む読みを正しく分割・判定する。

### コンポーネント・画面テスト

- ホームからゲームページへ遷移できる。
- 画像、文字タイル、進捗、操作ボタンが表示される。
- 文字数が揃うまで「できた！」が無効または非表示になる。
- 不正解後に「もういちど」が表示され、文字を戻して再挑戦できる。
- 5問完了後に結果画面へ進む。
- 結果画面から再プレイとホームへ戻る操作ができる。

### 完了確認

既存のテストに加えて、次のコマンドを実行する。

```bash
npm run typecheck
npm run test
npm run build
```

## 受入条件

- ホーム画面から独立ゲームを開始できる。
- 作成済みの既存画像が表示される。
- 5問を最後まで遊べる。
- 文字をバラバラの状態から正しい順番に並べられる。
- 「ー」を含む読みを扱える。
- 同じ文字が複数ある言葉で、どちらの同じ文字タイルを選んでも正解になる。
- 間違いをその場でやり直せる。
- 5問終了後に結果画面が表示される。
- 既存のかなクイズと書き順練習が壊れていない。
