# ManabiNote 書き順なぞり練習MVP 設計仕様

## 1. 文書情報

- 作成日: 2026-07-31
- 対象: 幼児向け・ひらがな書き順練習の試作
- 対象文字: あ、い、う、え、お
- 状態: 設計承認済み、実装前
- 実装ブランチ: feature/manabinote-stroke-order

## 2. 目的

幼児が薄いSVGのお手本をなぞりながら、ひらがなの書き順を練習できる機能を追加する。
1画ずつ順番に入力させることで、文字全体を自由に描く機能ではなく、書き始める位置、線の方向、画の順番を練習できるようにする。

既存の「ひらがなを見て絵を選ぶ」学習機能は変更せず、書き順練習を独立した機能として追加する。
バックエンド、データベース、ログイン、外部APIは使用しない。

## 3. MVPの範囲

### 含める機能

- ホーム画面から書き順練習を開始できる
- あ、い、う、え、おを固定順で1文字ずつ練習できる
- 文字を1画ずつ表示し、現在の画だけを入力対象にする
- 薄いSVGのお手本を表示する
- マウス、タッチ、ペンのPointer Eventsでなぞれる
- 開始位置、線上の進行、終点を基準に成功・失敗を判定する
- 成功した画を固定表示し、次の画へ進む
- 失敗時は減点せず、同じ画をやり直せる
- 現在の画、現在の文字、全体の進捗を表示する
- 5文字完了後に結果画面を表示する
- 結果画面からもう一度練習またはホームへ戻れる
- 既存の静的ビルド、PWA、オフラインキャッシュで利用できる

### 含めない機能

- ひらがな46文字以上への拡張
- カタカナ、漢字、数字の書き順
- 文字全体を自由に書いた後の総合的な手書き認識
- AIによる手書き判定
- 音声読み上げ
- ログイン、サーバー保存、端末間同期
- 書き順練習結果の履歴画面への保存
- ランキング、課金、複雑なコンボやライフシステム

履歴保存は既存の絵クイズのデータ形式と目的が異なるため、5文字の操作感を検証する今回の試作では追加しない。将来必要になった時点で、書き順用の履歴形式と保存キーを別途設計する。

## 4. 技術方針

- フロントエンド: 既存のReact + TypeScript + Vite
- ルーティング: 既存のHashRouter
- 描画: SVG viewBox 0 0 200 200
- 入力: Pointer Events。pointer captureを使用して画面外への一時的な移動にも対応する
- 問題データ: TypeScriptから分離したJSON
- 状態管理: 書き順練習専用のReact Contextと純粋な状態遷移関数
- 保存: MVPでは永続保存なし
- 外部依存: 外部画像、外部フォント、外部APIなし
- アクセシビリティ: 見出し、進捗テキスト、aria-liveによる結果通知、キーボードでの再試行・画面遷移

既存のQuizSessionProviderとクイズモデルは現在の問題形式に特化しているため、今回のMVPでは共通化や大規模なリファクタリングをせず、書き順専用のProviderとセッションモデルを追加する。

## 5. 画面構成と遷移

    ホーム
      └─ 書き順れんしゅう → 書き順練習

    書き順練習
      ├─ 画をなぞる
      ├─ 成功 → 次の画
      ├─ 失敗 → 同じ画をやり直す
      ├─ 文字の全画終了 → 次の文字へ
      └─ 5文字終了 → 書き順結果

    書き順結果
      ├─ もう一度練習 → 書き順練習
      └─ ホームへ戻る → ホーム

ルートは次の2つを追加する。

- /stroke-order: 練習画面
- /stroke-order/result: 結果画面

練習画面へ直接アクセスしてセッションが存在しない場合は、エラーを投げず、練習開始ボタンとホームへのリンクを表示する。

## 7. 書き順データモデル

strokes.jsonは5件の文字問題を持つ。問題の順番は配列順ではなく、kanaの固定配列で検証して明示する。

    {
      "type": "kana-to-stroke",
      "id": "hiragana-a",
      "kana": "あ",
      "viewBox": "0 0 200 200",
      "strokes": [
        {
          "order": 1,
          "guidePath": "M ...",
          "checkpoints": [
            { "x": 72, "y": 24 },
            { "x": 68, "y": 74 },
            { "x": 62, "y": 126 }
          ]
        }
      ]
    }

実装上の型は次の責務を持つ。

- StrokePoint: SVG viewBox上のx、y
- StrokeDefinition: 画順、表示用guidePath、判定用checkpoints
- KanaToStrokeQuestion: 問題形式、ID、kana、viewBox、画配列
- KanaToStrokeQuestion[]: あ、い、う、え、おの5件

validatorは次を確認する。

- 入力が配列である
- typeがkana-to-strokeである
- 問題IDとkanaが重複していない
- 対象文字がちょうど「あいうえお」である
- viewBoxが固定値である
- strokesが1件以上ある
- 画順が1から連続している
- guidePathが空でない
- checkpointsが2点以上あり、座標がviewBox内にある

表示用パスと判定用checkpointsは、書き順の正確さを担保するため、AnimCJKの日本語かなSVGに含まれるメディアン線を200×200の座標へ変換して作成する。表示用guidePathは折れ点が角張らないようBezier曲線へ整え、checkpointsは元の書き順線に沿って保持する。出典とライセンスは `src/features/question-types/kana-to-stroke/data/README.md` に記録する。

## 8. なぞり判定

StrokeCanvasは、現在の画のguidePathを薄い背景線として表示し、ユーザーの入力を別のSVG pathとして重ねる。
pointerdown、pointermove、pointerup、pointercancelを受け取り、クライアント座標をSVGのviewBox座標へ変換する。

判定手順は次の通り。

1. pointerdownが最初のcheckpointから許容距離以内か確認する
2. pointermoveごとに入力点を記録する
3. 現在のcheckpointを順番に進め、入力点が許容距離内に到達したら進捗を更新する
4. 入力が線から大きく外れた場合は失敗にする
5. pointerup時に最後のcheckpoint付近まで進んでいることを確認する
6. 条件を満たせば成功、満たさなければ失敗にする

初期の許容値はSVG座標で次のように定義する。

- 開始位置の許容距離: 26
- checkpointの許容距離: 28
- 終点の許容距離: 30
- 入力点が少なすぎる場合: 失敗

許容値は文字データと同じく定数または判定オプションとして管理し、テストで調整できるようにする。判定は全ての点が完全一致することを求めず、幼児のタッチ操作に合わせて許容幅を持たせる。

成功時は現在の画を完了済みとして表示し、次の画を入力対象にする。現在の文字の最後の画が成功したときは、成功メッセージと「つぎの文字へ」ボタンを表示する。

失敗時は次の動作にする。

- 減点しない
- 入力線を消す
- 現在の画を維持する
- 「もういちど なぞってみよう」とaria-liveで通知する
- 開始点と進行方向のヒントを表示する

pointercancelや入力中の画面離脱も、現在の画の失敗として扱い、次の画へは進めない。

## 9. セッション状態と結果

書き順練習のセッションは、次の状態を持つ。

- questions: 固定順の5問
- currentQuestionIndex: 0から4
- currentStrokeIndex: 現在の文字内の画番号
- completedCharacters: 完了した文字数
- attempts: 文字ごとのなぞり試行回数
- status: ready、drawing、stroke-complete、character-complete、complete、error

練習開始時は必ず「あ」から開始し、問題選択のランダム性は持たせない。
文字内の画順もstrokesのorderに従い、ユーザー入力で順番をスキップできないようにする。

結果画面では次を表示する。

- 「5もじ できたよ」という完了メッセージ
- あ、い、う、え、おの完了一覧
- 必要に応じて各文字の試行回数
- もう一度練習するボタン
- ホームへ戻るリンク

失敗回数を減点や失格条件に使わない。結果は「最後まで練習できた」ことを中心に表示する。

## 10. エラー処理

- JSONが壊れている場合は、練習画面に問題データエラーを表示する
- 5文字以外のデータや画順不正は、開始前に検出する
- 直接結果画面へアクセスして結果がない場合は、回復可能なメッセージとホームリンクを表示する
- Pointer Eventsがキャンセルされた場合は現在の画をリセットする
- 判定エラーが起きても既存の絵クイズ画面へ影響させない
- エラー文は幼児または保護者が理解できる平易な日本語にする

## 11. テスト方針

実装時はテストを先に作成する。

### モデル・データ

- 正常な5文字データを読み込める
- type、文字数、重複ID、画順、checkpoint座標の不正を拒否する
- 開始位置付近からcheckpointを順に通る入力を成功にする
- 開始位置不正、脱線、逆方向、終点未到達を失敗にする
- 失敗後に同じ画を再試行できる
- 文字内の最後の画から次の文字へ進める
- あからおまで固定順に進み、5文字で完了する

### コンポーネント・画面

- お手本SVGと現在の画番号を表示する
- pointer入力で成功した画が完了状態になる
- 失敗時に入力線が消え、通知とヒントが表示される
- 5文字完了後に結果画面へ進める
- 結果がない状態の直接アクセスが回復可能である
- ホームから書き順練習へ遷移できる

### 完了時の検証

- npm run test
- npm run typecheck
- npm run build
- npm run test:coverage

既存の絵クイズ、履歴、PWAテストが引き続き成功することも確認する。

## 13. 失敗後の書き順色表示

書く前から現在の画がオレンジ色になると、どの画を自分でなぞるべきかを考える前に答えが見えてしまうため、色付きの書き順表示は最初の失敗後に限定する。

- 初期状態では、現在の画を含むお手本線を薄いグレーで表示する
- 最初の失敗後は、現在の画をオレンジ色にし、開始マークと矢印を表示する
- 成功した画は従来どおり青色で固定し、成功後に進む次の画は薄いグレーから開始する
- 「文字を なぞろう」の案内文は初期状態から常に表示する
- `StrokeOrderPage` の失敗状態を `showFailureHint` として `StrokeCanvas` に渡し、色付きガイドと開始ヒントの表示条件を統一する

判定ロジック、SVGデータ、画面レイアウト、モバイル操作時のスクロール抑止は変更しない。初期表示、失敗後、成功後の表示状態をコンポーネントテストで確認する。
